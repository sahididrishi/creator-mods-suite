# creator_arsenal — asset inventory

Nothing in this list is finished art. Every PNG is generated by `tools/make_placeholders.py`
(python3 stdlib only) and every sound by `tools/make_sounds.sh` (ffmpeg synthesis only). They are
deliberately flat — three tones per material, a hard one-pixel key line, no shading ramps, no
sampled audio — but they are **readable**: each sprite carries the silhouette of the weapon it
stands for and each sound is the right shape for its role, so a placeholder take still reads on
camera. One palette runs through all six textures; it is documented at the top of the generator.

Regenerate the placeholders:

```bash
python3 common/src/main/java/dev/riftal/creator/features/arsenal/tools/make_placeholders.py
bash    common/src/main/java/dev/riftal/creator/features/arsenal/tools/make_sounds.sh
```

**Audio: mono, positional (fixed).** All of these `.ogg` files are **1-channel, 44.1 kHz
Ogg Vorbis**, so Minecraft applies normal 3D positional attenuation and panning to them. They were
converted with `ffmpeg -ac 1 -ar 44100` piped into `oggenc` (vorbis-tools) — ffmpeg's *native*
`vorbis` encoder is still stereo-only and cannot be used on its own; see CONTRACT.md §9.2.
Replacement assets must stay **mono, 44.1 kHz**.

## Sounds this feature plays

Three are ours (above); the rest are vanilla and need no asset:
`entity.fishing_bobber.throw` (hook fired), `item.trident.return` (line cut),
`entity.lightning_bolt.impact` and the bolt's own thunder, `block.beacon.power_select` (hammer
lift), `block.anvil.land` (slam), `entity.player.attack.sweep` (scythe sweep),
`particle.soul_escape` (a soul leaving a corpse).

## Known gaps

* **No bow draw animation.** Vanilla's `pull` / `pulling` model predicates are registered through
  `ItemProperties.register(Item, ResourceLocation, ClampedItemPropertyFunction)`, which is
  **`private`** in the 1.21.1 sources `:common` compiles against
  (`net/minecraft/client/renderer/item/ItemProperties.java:53`), and the two predicates are
  registered for `Items.BOW` specifically rather than generically (same file, lines 97 and 113), so
  a third-party bow cannot borrow them from JSON either. There is no core hook for per-feature
  client setup on either loader. The Storm Bow therefore uses one static model with vanilla's bow
  display transforms; `storm_bow_pulling_0..2` textures and the `overrides` block are deliberately
  **not** shipped, because they would never be selected. If core ever exposes a client-side
  item-property hook, add the three pulling textures and the overrides at the same time.
* **No GameTest arenas of our own.** Only the shared `data/creator_arsenal/structure/empty.nbt`
  exists, and every GameTest works inside it — the grapple test builds its own wall with
  `helper.setBlock` rather than shipping a `cliff_gap` template. Plan 07's `arena_16x8` and
  `cliff_gap` templates need a dev client (`/test create` + `/test export`) and are not required by
  anything currently in the suite.
* **No GeckoLib models.** Both entities render with vanilla-style renderers (a camera-facing quad
  plus a `RenderType.lineStrip()` rope for the hook, `ArrowRenderer` for the arrow), so there is no
  `geo/` or `animations/` directory and none is needed. Plan 07 lists 3D scythe/hammer models as a
  stretch goal.
* **No Better Combat `weapon_attributes` JSON.** Stretch goal in plan 07 section 3; skipped under
  the MVP-only rule.
